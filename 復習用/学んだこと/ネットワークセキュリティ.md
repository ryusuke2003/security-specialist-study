# ネットワークセキュリティ

## 2026-08-23

### IPsecトンネルモード

- IPsecのトンネルモードは、元のIPパケット全体を保護し、新しいIPヘッダで包む。拠点間VPNのように、二つの社内ネットワークをゲートウェイ間で接続する用途に適する。
- IKEは相互認証と暗号方式・鍵などのSecurity Association確立を担い、ESPは確立した設定で実データを暗号化し完全性も保護する。
- IKEv2では、まずDH鍵共有・暗号方式の交渉でIKEメッセージ用の鍵を導出し、続いて相互認証と保護対象ネットワークの合意を行う。そこで方向ごとのIPsec SA（SPI・ESP用鍵・暗号方式・通信範囲）を確立してから、ESPで実データを包む。流れは[IPsecトンネルモードとIKE](../流れ図/IPsecトンネルモードとIKE.md)を参照。

### トランスポートモードとトンネルモードを分ける理由

- **トランスポートモード**は、元のIPヘッダを残し、そのペイロードをIPsecで保護する。通信する二つの端末自身がIPsecの終端であり、元の宛先IPアドレスへそのまま届けられるホスト間通信に向く。追加のIPヘッダがないため、トンネルモードよりオーバーヘッドが小さい。
- **トンネルモード**は、元のIPパケット全体を内側のパケットとして保護し、外側に新しいIPヘッダを付ける。インターネット上では、まず外側の宛先であるVPN装置（VPNゲートウェイ）へ届ける必要があるため、この「VPN装置までの住所」が必要になる。VPN装置が外側ヘッダを外すと、内側に残った本来の宛先IPアドレスを使って社内ネットワークへ転送できる。
- つまり、**本来の宛先とIPsecの終端が同じならトランスポートモード、本来の宛先とは別のVPN装置を経由させるならトンネルモード**と考えると区別しやすい。拠点間VPNでは内部端末のアドレスを外部へ見せず、ネットワーク全体をゲートウェイ間でつなげられるため、通常はトンネルモードを使う。

## 2026-08-24

### IKE・SA・SPI・ESPのつながり

- IPsecはIP層で通信を保護する仕組みであり、拠点間VPN、リモートアクセスVPN、ホスト間通信に使える。Web/APIなどアプリケーション単位の保護にはTLS/HTTPSが一般的だが、両者は層が異なるため併用もできる。
- IKE（Internet Key Exchange）は、共通鍵そのものを相手へ送る仕組みではない。DH/ECDHEなどで公開情報を交換して双方が同じ共有秘密を計算し、nonceなどとともに鍵を導出する。相手認証・暗号方式の交渉も行い、IKE用の鍵とESP用の鍵は用途を分けて導出する。
- SA（Security Association）は、暗号方式・鍵・SPI・有効期限・連番状態・相手・保護対象の通信範囲などから成る、通信を保護するための設定一式である。IKEで確立した後も、ESPがパケットごとに参照する。通常は送信方向と受信方向で別々のSAを持つ。
- SPI（Security Parameters Index）はESPヘッダに入る、受信側が対応するSAを探すための識別番号である。SPI自体は秘密ではない。攻撃者がSPIをまねても、対応SAの鍵で検証できる正しい認証データを作れないため、偽造パケットは破棄される。
- ESPはSAをSPIで特定して、実データを暗号化し、構成に応じて完全性・通信相手の真正性・リプレイ対策を提供する。AES-GCMなどAEADを使う場合は、暗号化と認証タグ生成を一体で行う。受信側は連番も確認するため、過去の正しいESPパケットの単純な再送も防ぐ。

### ESPが保護する範囲と主な用途

- **トランスポートモード**は元のIPヘッダを残し、主にIPペイロード（TCP/UDPヘッダとデータ）を保護する。IPsec終端が通信端末そのものとなるホスト間通信に向く。
- **トンネルモード**は元のIPヘッダを含むIPパケット全体をESPで保護し、その外側にVPNゲートウェイ宛ての新しいIPヘッダを付ける。拠点間VPNだけでなく、利用者端末から会社のVPNゲートウェイへ接続するリモートアクセスVPNでもよく使う。したがって、VPNの種類だけでモードを決めるのではなく、IPsec終端と本来の通信先が同じかで考える。
- 一言でまとめると、**IKEが「どう守るか」を合意してSAを作り、ESPがそのSAに従って実際のIP通信を守る**。具体的な交換からトンネル通信までの流れは[IPsecトンネルモードとIKE](../流れ図/IPsecトンネルモードとIKE.md)を参照。
