# ログ分析・監視

## 2026-08-17

### EDRテレメトリと検知ユースケース

- EDRテレメトリは、端末上で収集するプロセスツリー、コマンドライン、ファイル、ハッシュ、ネットワーク通信などの行動データである。端末の不審な挙動の検知・調査・隔離に使う。
- 検知ユースケースは「何を不審とみなすか」と「どのログ条件で検知するか」を定義する設計単位である。検知ルールは、攻撃手法との対応だけでなく、誤検知を抑える条件と調査時に必要な情報も考慮する。

## 2026-09-05

### EDRはエージェント・テレメトリ・分析・対応を含む仕組み全体

- `EDR`は**Endpoint Detection and Response**の略で、PCやサーバーなどのエンドポイント上の活動を継続的に観測し、不審な挙動の検知、調査、封じ込め・対応につなげる製品・仕組み全体を指す。
- **EDRエージェント**は、典型的には端末へ導入するセンサー兼実行部である。OSからプロセスの親子関係・コマンドライン、ファイルやレジストリの変更、ログオン、ネットワーク接続などを収集し、分析基盤から届く隔離・プロセス停止・ファイル検疫などの指示も端末上で実行する。製品によってはエージェントレス方式もあるため、エージェントは代表的な構成要素であってEDRの定義そのものではない。
- **EDRテレメトリ**は、エージェントなどが収集して分析基盤へ送る観測データである。プログラムや製品名ではない。個々のイベントに端末ID、利用者、時刻、プロセスID、親プロセス、ハッシュ、通信先などの文脈を付けることで、複数イベントを一連の攻撃として追跡しやすくする。
- **分析・管理基盤**は、テレメトリを受信・保存し、検知ルール、振る舞い分析、脅威情報などと相関させる。不審な組合せを検出した場合は、端末・利用者・プロセスツリー・時系列などの根拠をまとめてアラートを作る。
- **管理コンソール**は、SOC担当者やインシデント対応者がアラートを確認し、検索・タイムライン調査・脅威ハンティングを行い、必要な対応を指示する入口である。製品や設定によっては、事前に定めた条件で対応を自動実行できる。
- したがって、`エージェント + テレメトリ = EDR`ではない。**エージェントなどでテレメトリを収集し、基盤で分析・検知し、人または自動化が調査・対応する一連の能力がEDR**である。
- データの向きと指示の向きは逆である。観測時は「端末のエージェント → 分析基盤」へテレメトリが上がり、対応時は「SOC担当者／自動化 → 分析基盤 → 端末のエージェント」へ隔離などの指示が下る。具体的な流れは[EDRテレメトリの収集・分析・対応](../流れ図/EDRテレメトリの収集・分析・対応.md)を参照する。
- EDRは万能ではない。収集対象外のイベント、停止・改ざんされたエージェント、オフライン端末、保存期間外のデータ、正常な管理操作に見せかける攻撃などは検知できない場合がある。検知ルールの調整、エージェントの健全性監視、ログ保全、SIEMやネットワーク監視、バックアップなどと組み合わせる。
- EPPや従来型アンチウイルスは主に既知マルウェアなどの侵入・実行防止へ重点を置き、EDRは侵入後も含む継続監視・調査・対応へ重点を置く。ただし実製品では両機能を一体で提供することが多いため、製品名だけでなく実装されている能力を確認する。
