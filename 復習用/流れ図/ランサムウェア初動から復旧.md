# ランサムウェア初動から復旧

## 前提と登場人物

これは組織のインシデント対応の概略である。**CSIRTが判断・調整し、ネットワーク担当が隔離、調査担当が証拠保全、復旧担当が復元する**。小規模な組織では一人が複数の役割を兼ねることもある。

図は判断のつながりを示すもので、全作業を必ず直列に終える手順ではない。被害拡大防止と証拠保全は並行して調整し、業務・人命への影響も考慮する。

## 1. 対応チームが被害拡大を止め、範囲を調べる

```mermaid
flowchart TB
    D["SOCまたは利用者が<br/>暗号化・不審通信等を検知する"]
    C["CSIRTが事象を評価し<br/>対応担当と隔離対象を決める"]
    N["ネットワーク担当が感染疑い端末・共有等を隔離し<br/>横展開と外部通信を制限する"]
    F["調査担当がログ・メモリ等を保全し<br/>操作時刻と証拠の出所を記録する"]
    I["調査担当が他端末・認証情報・バックアップまで<br/>侵害範囲と侵入経路を調べる"]
    E["対応チームが侵入経路を塞ぎ<br/>侵害アカウント・セッション等を無効化する"]
    D --> C
    C --> N
    C --> F
    N --> I
    F --> I
    I --> E
```

端末一台やDBだけを隔離して完了とはしない。バックアップ基盤へのアクセスも保護する。揮発性の証拠を失うため電源断を機械的な初手にはせず、通信遮断の可否と被害状況に応じて判断する。

## 2. 復旧担当が条件を確認して段階的に戻す

```mermaid
flowchart TB
    B{"復旧担当がバックアップの<br/>健全性と復元可能性を確認できたか？"}
    T{"対応チームが復旧先の侵害除去と<br/>再侵入対策を確認できたか？"}
    R["復旧担当が隔離されたクリーンな環境へ<br/>優先度順に復元し、動作を検証する"]
    A{"CSIRTと業務責任者が<br/>再接続と業務再開を承認したか？"}
    M["運用担当が段階的に再接続し<br/>SOCが再発・横展開の兆候を監視する"]
    S["対応チームが復旧・再接続を保留し<br/>不足条件を調査・是正する"]
    B -->|はい| T
    B -->|いいえ| S
    T -->|はい| R
    T -->|いいえ| S
    R --> A
    A -->|はい| M
    A -->|いいえ| S
```

## 処理後に残るもの

| 主体 | 保持するもの・結果 |
|---|---|
| CSIRT | 影響範囲、意思決定、連絡記録、再発防止課題 |
| 調査担当 | 保全証拠、時系列、侵入・横展開の調査結果 |
| 復旧・運用担当 | 検証済み復元データ、変更記録、クリーンな環境 |
| SOC | 復旧後の監視条件と検知・対応記録 |

## 注意点

復元できたことと、侵害を取り除けたことは別である。バックアップが存在するだけでも復旧可とは判断しない。情報流出の評価、組織内外への連絡、必要な報告、教訓の反映も対応の一部だが、この図は技術的な封じ込めから復旧を中心に示している。
