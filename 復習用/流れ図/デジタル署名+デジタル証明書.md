# デジタル署名とデジタル証明書

## 前提と登場人物

**送信者はデータへ署名し、受信者は「検証鍵を信用できるか」と「データの署名が正しいか」を別々に確認する。** ここではAliceの文書署名用証明書がCAから発行済みで、Bobは信頼済みCAをローカルに設定済みとする。

この図は署名と証明書の役割に集中し、データの暗号化は含めない。機密性が必要ならTLSや暗号化コンテナ等を別途使う。証明書の申請・発行処理と受信時の検証処理を混ぜない。

## Bobが証明書を検証してからデータの署名を検証する

```mermaid
sequenceDiagram
    autonumber
    participant A as Aliceの署名アプリ
    participant B as Bobの検証アプリ

    A->>A: Aliceのアプリが署名用秘密鍵で文書Mの署名を生成する
    A->>B: Aliceのアプリが文書M・署名・Aliceの証明書・必要な中間証明書を送る
    B->>B: Bobのアプリがローカルの信頼済みCAを起点に証明書チェーンを検証する
    B->>B: Bobのアプリが証明書の期限・用途・失効方針・期待する署名者との対応を確認する
    alt Bobのアプリが証明書を信用できないと判断した
        B->>B: BobのアプリがAliceとしての署名を受け入れない
    else Bobのアプリが証明書を信用できると判断した
        B->>B: Bobのアプリが証明書内のAliceの公開鍵を取得する
        B->>B: Bobのアプリが公開鍵・受信文書M・署名を署名検証へ入力する
        alt Bobのアプリが署名を有効と判定した
            B->>B: Bobのアプリが対応する秘密鍵による署名と文書の完全性を確認する
        else Bobのアプリが署名を不正と判定した
            B->>B: Bobのアプリが文書を正当な署名付きデータとして受け入れない
        end
    end
```

## 処理後に残るもの

| 主体 | 保持するもの | 相手へ渡さないもの |
|---|---|---|
| Aliceの署名アプリ | Aliceの秘密鍵・証明書・文書 | 秘密鍵はBobへ送らない |
| Bobの検証アプリ | 信頼済みCA情報、受信文書・署名・証明書、検証結果 | AliceやCAの秘密鍵は不要 |
| CA | 発行ポリシー・発行記録・CA秘密鍵 | CA秘密鍵は証明書に含めない |

## 注意点

CAの署名は**証明書内の公開鍵と識別情報の結び付き**を支える。Aliceの署名は**文書M**を対象にする。この二つの署名は、署名者・署名対象・検証鍵が異なる。

証明書を受け取っただけで信用するのではなく、事前の信頼情報につながるか確認する。署名が有効でも内容の無害性や最新性まで保証しない。署名単体の処理は[デジタル署名](デジタル署名.md)、TLS用途の検証は[証明書チェーン検証](証明書チェーン検証.md)を参照する。
