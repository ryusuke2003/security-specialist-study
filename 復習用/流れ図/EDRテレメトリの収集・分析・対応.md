# EDRテレメトリの収集・分析・対応

EDRでは、**観測データは端末から分析基盤へ送り、対応指示は分析基盤から端末へ返す**。エージェントとテレメトリは構成要素であり、収集・分析・調査・対応までを含む仕組み全体がEDRである。

## 収集から対応まで

```mermaid
sequenceDiagram
    autonumber
    participant Endpoint as 端末上のOS／アプリ
    participant Agent as EDRエージェント（端末内）
    participant Platform as EDR分析・管理基盤
    actor Analyst as SOC担当者／インシデント対応者

    Endpoint-->>Agent: OSがプロセス起動、コマンドライン、ファイル変更、ログオン、通信などのイベントを通知する
    Agent->>Agent: エージェントが端末ID、利用者、時刻、プロセスID、親子関係、ハッシュなどの文脈を付ける
    Agent->>Platform: エージェントが保護された通信でイベントと文脈をEDRテレメトリとして送る
    Platform->>Platform: 分析基盤がテレメトリを正規化・保存し、検知ルールや振る舞い分析でイベントを相関する
    alt 分析基盤が不審な挙動を検知した
        Platform-->>Analyst: 分析基盤が端末・利用者・プロセスツリー・時系列・検知根拠を含むアラートを表示する
        Analyst->>Platform: SOC担当者が端末ID、利用者、ハッシュ、時刻などの条件で関連テレメトリを検索する
        Platform-->>Analyst: 分析基盤が関連イベント、端末状態、過去のアラートを調査結果として返す
        Analyst->>Platform: SOC担当者が対象端末と、隔離・プロセス停止・ファイル検疫などの対応内容を指定する
        Platform->>Agent: 分析基盤が対象端末のエージェントへ認証済みの対応コマンドを送る
        Agent->>Endpoint: エージェントが指定されたネットワーク隔離、プロセス停止、ファイル検疫などを実行する
        Agent-->>Platform: エージェントが実行結果、実行時刻、現在の端末状態を返す
        Platform->>Platform: 分析基盤が対応結果と実行者を監査ログへ保存する
    else アラート条件に一致しない
        Platform->>Platform: 分析基盤が保持方針に従ってテレメトリを保存し、後日の検索・相関分析に備える
    end
```

自動対応を設定している場合は、SOC担当者による指示の代わりに、分析基盤が事前承認されたポリシーに基づいて対応コマンドを送る。誤検知による業務停止を避けるため、自動化する操作と人の承認を必要とする操作を分ける。

## 処理後に誰が何を保持するか

| 主体 | 主に保持するもの | 主な役割・注意点 |
|---|---|---|
| 端末上のEDRエージェント | 収集設定、端末識別情報、送信前の一時バッファ、直近の対応状態など | イベントを収集して送信し、分析基盤から届いた対応を端末上で実行する |
| EDR分析・管理基盤 | 受信したテレメトリ、端末・利用者との対応、検知ルール、アラート、調査結果、対応の監査ログ | 複数イベント・複数端末を相関し、検知・検索・対応指示を行う |
| SOC担当者／インシデント対応者 | 調査判断、インシデント記録、対応方針 | 管理コンソールを通じて基盤内のデータを参照し、必要な対応を決める |
| 端末上のOS／アプリ | 実行中のプロセス、ファイル、設定、通信状態など | 監視される対象であり、隔離や停止などの対応によって状態が変わる |

テレメトリには利用者名、コマンドライン、ファイルパス、通信先などの機微情報が含まれ得る。分析基盤ではアクセス制御、暗号化、保存期間、監査ログを設定し、調査に必要な範囲を超えて利用できないようにする。

## EDRだけでは埋められない範囲

- エージェントが停止・改ざんされた端末や、ネットワークから切断された端末では、テレメトリ送信や遠隔対応が遅延・失敗することがある。
- 収集していないイベントや保存期間を過ぎたイベントは、後から分析できない。
- EDRが主に観測するのはエンドポイントである。ネットワーク機器、クラウド制御プレーン、SaaSなどの記録は、SIEM、NDR、クラウド監査ログなどで補う。
- 端末隔離やマルウェア除去は復旧の一部であり、漏えいした認証情報の無効化、影響範囲調査、脆弱性修正、バックアップからの復元などは別途必要になる。
