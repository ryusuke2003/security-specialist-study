# 2026-09-04に復習するべきところ

採点日: 2026-09-03

#### CORS — 0点

- [x] 復習済み

出典: [2026-08-26 / Session 2 / Q7](../../学習記録/理解・応用問題/2026-08-26.md#q7)

**復習の要点**: CORSはクロスオリジンの通信自体を禁止するのではなく、別オリジンのJavaScriptがレスポンスを読めるかをブラウザが制御する仕組みである。認証情報付きの`PATCH`ではpreflightが行われ得る。許可するOriginは具体的に指定し、`*`と認証情報の許可を併用しない。

- 流れ図: [CORSのpreflightと認証情報付きリクエスト](../流れ図/CORSのpreflightと認証情報付きリクエスト.md)
- 関連する新語: `同一オリジンポリシー` — ブラウザ上の文書・JavaScriptが、原則として別オリジンのリソースを自由に読み取れないようにする基本原則。

#### 情報セキュリティ方針と規程 — 0点

- [x] 復習済み

出典: [2026-08-26 / Session 2 / Q8](../../学習記録/理解・応用問題/2026-08-26.md#q8)

**復習の要点**: 方針は組織全体の原則、標準は守る共通要件、手順は担当者の具体的な作業順序である。規程は作成するだけでなく、周知・教育、順守確認、運用、定期見直しが必要である。

- 関連する新語: `ISMS` — 方針、責任、管理策、運用、監査、改善を継続的に回し、情報セキュリティリスクを管理する仕組み。

#### DMARC — 15点

- [x] 復習済み

出典: [2026-08-26 / Session 2 / Q2](../../学習記録/理解・応用問題/2026-08-26.md#q2)

**復習の要点**: DMARCはSPF又はDKIMがpassであるだけでは足りない。passしたSPFのenvelope-from又はDKIMの`d=`が、表示上のFromドメインとalignmentして初めてDMARC passとなる。

- 関連する新語: `DKIM` — 送信側が本文と選択ヘッダへ秘密鍵で署名し、受信側がDNSの公開鍵で検証する仕組み。

#### AEAD — 25点

- [x] 復習済み

出典: [2026-08-26 / Session 2 / Q1](../../学習記録/理解・応用問題/2026-08-26.md#q1)

**復習の要点**: AEADは暗号化と認証タグで機密性・改ざん検知を提供する。同一鍵でnonceを再利用すると同じ暗号用マスクが使われ得て安全性が崩れ、AES-GCMでは偽造タグにもつながり得る。タグ検証に失敗したデータは利用せず破棄する。

- 流れ図: [AEADの暗号化と認証タグ検証](../流れ図/AEADの暗号化と認証タグ検証.md)
- 関連する新語: `MAC` — 共有秘密鍵とメッセージから認証子を作り、改ざんと鍵を知る者による作成を確認する仕組み。

#### CRL / OCSP — 45点

- [x] 復習済み

出典: [2026-08-26 / Session 2 / Q3](../../学習記録/理解・応用問題/2026-08-26.md#q3)

**復習の要点**: CRLは失効証明書一覧を取得して照合し、OCSPは対象証明書の失効状態を個別に問い合わせる。OCSP staplingではサーバが取得済みのOCSP応答をTLSハンドシェイクで提示するため、クライアントの直接照会を減らせる。

- 流れ図: [CRLとOCSPの失効確認](../流れ図/CRLとOCSPの失効確認.md)
- 関連する新語: `OCSP stapling` — サーバがCAから得たOCSP応答をクライアントへ提示し、失効確認の遅延・プライバシー上の懸念を抑える方式。

#### Windows AD / Kerberos — 55点

- [x] 復習済み

出典: [2026-08-26 / Session 2 / Q5](../../学習記録/理解・応用問題/2026-08-26.md#q5)

**復習の要点**: ドメインコントローラはADを管理し、KerberosのKDCも担う。利用者はTGTを使い、対象サービスを示すSPNに対応するサービスチケットを取得して提示する。パスワードを各サービスへ毎回送らないことで露出を減らす。

- 流れ図: [Active DirectoryとKerberosのチケット認証](../流れ図/ActiveDirectoryとKerberosのチケット認証.md)
- 関連する新語: `Kerberoasting` — サービスアカウントのSPNに対応するサービスチケットを取得し、オフラインでパスワードを解析しようとする攻撃。

#### 認証情報窃取 — 60点

- [x] 復習済み

出典: [2026-08-26 / Session 2 / Q6](../../学習記録/理解・応用問題/2026-08-26.md#q6)

**復習の要点**: LSASSへの不審なアクセスはcredential dumpingによる認証情報窃取を疑う兆候である。直後の認証失敗の多発と組み合わせて横展開を疑い、端末隔離、メモリ・ログ保全、影響アカウントの無効化や認証情報変更へ進む。

- 関連する新語: `credential dumping` — OSのメモリや資格情報ストアからパスワードハッシュ、チケットなどの認証情報を取り出そうとする攻撃手法。
