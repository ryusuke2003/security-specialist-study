# 2026-08-24に復習するべきところ

採点日: 2026-08-23

## 理解・応用問題

### 最優先

- 2026-08-14 Session 2 Q1 / `OAuth 2.0 / OIDC` / 5点: OAuth 2.0はAPIへの権限委譲である認可、OIDCはIDトークンを使う認証である。認可コードはブラウザへトークンを直接渡さずに交換するために使い、PKCEは横取りしたコードの交換を防ぐ。
  - 流れ図: [OAuth 2.0 / OIDCの認可コードとPKCE](../流れ図/OAuth2とOIDCの認可コードとPKCE.md)
  - 関連する新語: `IDベースのアクセス制御` — 利用者や端末などの識別情報とポリシーに基づきアクセスを制御する考え方。
- 2026-08-14 Session 2 Q2 / `AEAD` / 0点: AEADは暗号化と認証タグによる改ざん検知を同時に行う。同一鍵でnonceを再利用せず、認証タグの検証に失敗したデータは利用せず破棄する。
  - 関連する新語: `共通鍵暗号と公開鍵暗号` — 共通鍵暗号は同じ鍵で高速に暗号化・復号し、公開鍵暗号は公開鍵と秘密鍵の組で暗号化や署名に使う。
- 2026-08-14 Session 2 Q3 / `VPN（IPsec）` / 10点: トンネルモードは元のIPパケット全体を包み、拠点間ネットワークを接続する。IKEが鍵とSecurity Associationを確立し、ESPが実データを保護する。
  - 関連する新語: `ネットワークアクセス制御（NAC）` — 利用者・端末の認証や端末状態に応じて、ネットワーク接続を許可・制限する仕組み。
- 2026-08-14 Session 2 Q4 / `DKIM` / 35点: 送信側は秘密鍵で署名し、受信側は`selector._domainkey.署名ドメイン`のDNS TXTから公開鍵を取得して検証する。DKIMだけで表示上のFromの正当性は決めず、DMARCでalignmentとポリシーも確認する。
  - 流れ図: [DKIMの署名と検証](../流れ図/DKIMの署名と検証.md)
  - 関連する新語: `DMARC` — SPFまたはDKIMの結果と表示上のFromドメインとのalignmentを評価し、受信側の扱いを定める仕組み。
- 2026-08-14 Session 2 Q6 / `ゼロトラスト原則` / 20点: VPN接続済みでも無条件に信頼せず、利用者の本人性、端末健全性、要求内容を継続的に評価する。最小権限と細かなネットワーク分離で横展開を抑える。
  - 関連する新語: `端末健全性評価` — パッチ適用状況、EDR稼働、暗号化などを基に、端末がアクセスを許可できる状態か評価すること。

### 確認

- 2026-08-14 Session 2 Q5 / `インシデント対応ライフサイクル` / 78点: 封じ込めで通信・横展開を抑え、再起動前にメモリ・プロセス・接続情報・ログを保全する。その後に侵入経路と永続化を根絶し、健全性を確認して復旧する。初期化を急ぐと原因・影響範囲を調べる証拠を失う。
  - 流れ図: [ランサムウェア初動から復旧](../流れ図/ランサムウェア初動から復旧.md)
  - 関連する新語: `証拠保全と初動` — インシデント直後に、失われやすい証拠を保全しつつ被害拡大を抑える対応。
