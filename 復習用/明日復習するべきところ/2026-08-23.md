#### Webアクセスログ分析 — 45点

- [x] 復習済み

出典: [2026-08-14 / Session 1 / Q5](../../学習記録/理解・応用問題/2026-08-14.md#q5)

**復習の要点**: `../`を増やして`/etc/passwd`を指定しているため、公開されたダウンロード用ディレクトリの外へ到達し、OS上の任意ファイルを読もうとするディレクトリトラバーサルを疑う。403の後に200があるので成功の可能性はあるが、エラー画面を200で返す実装もあるため、200だけで読取り成功とは断定しない。

- アプリ・監査ログ: リクエストで**どの実ファイルを開いたか**、認可判定や例外を確認し、サーバ上のファイルを実際に読めたかを確かめる。
- WAF・リバースプロキシ・ネットワークログ: 200応答のバイト数、同じ送信元IPへの送信量、後続通信を確認し、読めた内容が攻撃者へ返りどこまで漏れたかを確かめる。
- WAFとは: Webアプリの前段でHTTPリクエストを検査し、`../`のような攻撃パターンを検知・遮断したり判定をログに残したりする仕組み。アプリの脆弱性を直す代わりではなく、攻撃を減らす境界防御として使う。
- 関連する新語: `ディレクトリトラバーサル` — `../`などで想定されたディレクトリ外のファイルへ到達し、任意ファイル読取りを狙う攻撃。

#### OAuth 2.0 / OIDC — 5点

- [x] 復習済み

出典: [2026-08-14 / Session 2 / Q1](../../学習記録/理解・応用問題/2026-08-14.md#q1-1)

**復習の要点**: OAuth 2.0はAPIへの権限委譲である認可、OIDCはIDトークンを使う認証である。認可コードはブラウザへトークンを直接渡さずに交換するために使い、PKCEは横取りしたコードの交換を防ぐ。

- 流れ図: [OAuth 2.0 / OIDCの認可コードとPKCE](../流れ図/OAuth2とOIDCの認可コードとPKCE.md)
- 関連する新語: `IDベースのアクセス制御` — 利用者や端末などの識別情報とポリシーに基づきアクセスを制御する考え方。

#### AEAD — 0点

- [x] 復習済み

出典: [2026-08-14 / Session 2 / Q2](../../学習記録/理解・応用問題/2026-08-14.md#q2-1)

**復習の要点**: AEADは暗号化と認証タグによる改ざん検知を同時に行う。同一鍵でnonceを再利用せず、認証タグの検証に失敗したデータは利用せず破棄する。

- 関連する新語: `共通鍵暗号と公開鍵暗号` — 共通鍵暗号は同じ鍵で高速に暗号化・復号し、公開鍵暗号は公開鍵と秘密鍵の組で暗号化や署名に使う。

#### DKIM — 35点

- [x] 復習済み

出典: [2026-08-14 / Session 2 / Q4](../../学習記録/理解・応用問題/2026-08-14.md#q4-1)
