# 2026-08-23に復習するべきところ

採点日: 2026-08-22

## 理解・応用問題

### 最優先

- 2026-08-14 Session 1 Q3 / `責任共有モデル` / 55点: IaaSでは、物理・ネットワーク・仮想化基盤はクラウド事業者、ゲストOSのパッチ・IAM・データ・設定は利用者が主に守る。不要なIAM権限を外し、OSパッチを適用する理由まで対応付ける。
  - 関連する新語: `クラウドIAMと一時資格情報` — クラウド上のロールや一時資格情報を使い、最小権限でアクセスを制御する仕組み。
- 2026-08-14 Session 1 Q4 / `XSS` / 55点: 投稿データを表示するときは、HTML本文や属性値など出力先の文脈に合ったエンコーディングを表示直前に行う。HttpOnlyはCookie窃取を抑える補助策で、XSS実行そのものの防止策ではない。
  - 流れ図: [入力検証と出力エンコーディング](../流れ図/入力検証と出力エンコーディング.md)
  - 関連する新語: `CSP` — ブラウザが読み込むスクリプトなどの出所を制限し、XSSの被害を抑えるHTTPレスポンスヘッダのポリシー。
- 2026-08-14 Session 1 Q5 / `Webアクセスログ分析` / 45点: `../`を増やして`/etc/passwd`を指定しているため、公開されたダウンロード用ディレクトリの外へ到達し、OS上の任意ファイルを読もうとするディレクトリトラバーサルを疑う。403の後に200があるので成功の可能性はあるが、エラー画面を200で返す実装もあるため、200だけで読取り成功とは断定しない。
  - アプリ・監査ログでは、リクエストを受けて**どの実ファイルを開いたか**、認可判定や例外がどうなったかを確認する。ここで「サーバ上のファイルを実際に読めたか」を確かめる。
  - WAF・リバースプロキシ・ネットワークログでは、200応答のバイト数、同じ送信元IPへの送信量、後続の通信を確認する。ここで「読めた内容が攻撃者へ返り、どこまで漏れたか」を確かめる。
  - **WAF（Web Application Firewall）**は、Webアプリの前段でHTTPリクエストを検査し、`../`のような攻撃パターンを検知・遮断したり、その判定をログに残したりする仕組みである。アプリの脆弱性を直す代わりではなく、攻撃を減らす境界防御として使う。
  - 関連する新語: `ディレクトリトラバーサル` — `../`などで想定されたディレクトリ外のファイルへ到達し、任意ファイル読取りを狙う攻撃。

### 軽い確認

- 2026-08-14 Session 1 Q6 / `入力検証と出力エンコーディング` / 92点: 入力検証はサーバ側で文字種・長さ・形式をallowlistで確認し、SQLにはプレースホルダで値を渡し、HTML属性値へ出力する直前には文脈に合うエンコーディングを行う。文字数だけでは許可しない文字種・形式を防げない。
  - 流れ図: [入力検証と出力エンコーディング](../流れ図/入力検証と出力エンコーディング.md)
  - 関連する新語: `XSS` — 入力データを安全に出力しないことで、閲覧者のブラウザに意図しないスクリプトを実行させる脆弱性。
