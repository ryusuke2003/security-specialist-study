# 2026-08-28に復習すること

- 採点日: 2026-08-27

#### WebAuthn / パスキー — 0点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q12](../../学習記録/暗記語句問題/2026-08-25.md#q12)

**復習の要点**: WebAuthn / パスキーは、認証器がRPごとに公開鍵資格情報を作り、秘密鍵でチャレンジへ署名して認証する。秘密鍵は認証器側に保持され、RP ID・オリジンに結び付くためフィッシングに強い。

- 関連する新語: `多要素認証` — 知識・所持・生体など異なる要素を組み合わせて本人確認を強める認証方式。

#### ネットワークセグメンテーション — 0点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q14](../../学習記録/暗記語句問題/2026-08-25.md#q14)

**復習の要点**: ネットワークを用途・信頼度ごとに区画化し、区画間通信をACLやファイアウォールで必要最小限に制御して、侵害時の横展開を抑える。

- 関連する新語: `ネットワークアクセス制御（NAC）` — 端末や利用者の認証・端末状態に応じてネットワーク接続を許可、制限、隔離する仕組み。

#### 電子署名 — 45点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q6](../../学習記録/暗記語句問題/2026-08-25.md#q6)

**復習の要点**: 電子署名は秘密鍵で作成し、対応する公開鍵で検証する。改ざん検知と署名者の確認を行い、条件が満たされれば否認防止に用いる。

- 流れ図: [デジタル署名](../流れ図/デジタル署名.md)
- 関連する新語: `ハッシュとMAC` — ハッシュは鍵なしの要約値、MACは共有秘密鍵を使って完全性と鍵保持者による作成を確認する認証子。

#### HTTPリクエストスマグリング — 50点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q11](../../学習記録/暗記語句問題/2026-08-25.md#q11)

**復習の要点**: フロントエンドとバックエンドで`Content-Length`・`Transfer-Encoding`などの解釈が異なると、リクエスト境界をずらして後続リクエストを送り込まれることがある。

- 関連する新語: `プロキシ / リバースプロキシ` — プロキシは通信を中継し、リバースプロキシはサーバ側の入口で要求を受けてバックエンドへ振り分ける。

#### 認証と認可の分離 — 50点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q15](../../学習記録/暗記語句問題/2026-08-25.md#q15)

**復習の要点**: 認証は利用者が誰かを確認し、認可は認証済み利用者に特定の操作・リソースを許可するか判定する。分離して最小権限と変更しやすさを保つ。

- 関連する新語: `RBAC / ABAC` — RBACはロール、ABACは利用者・リソース・環境などの属性に基づいて認可する方式。

#### 検知ユースケース — 55点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q2](../../学習記録/暗記語句問題/2026-08-25.md#q2)

**復習の要点**: 検知ユースケースは、検知したい事象、使うログ、判定条件、アラート後の対応を一組で定める。対策一般の計画ではない。

- 関連する新語: `SIEM相関分析` — 複数のログを時刻や利用者、端末などで関連付け、単一ログでは見えにくい不正を検知・調査する。

#### SSRF — 70点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q1](../../学習記録/暗記語句問題/2026-08-25.md#q1)

**復習の要点**: SSRFは、攻撃者指定のURLへWebサーバ自身からリクエストを送らせる攻撃であり、内部サービスやクラウドメタデータへの到達に悪用される。

- 関連する新語: `ネットワークセグメンテーション` — ネットワークを区画化し、区画間通信を制御して侵害時の横展開を抑える対策。

#### IDベースのアクセス制御 — 70点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q4](../../学習記録/暗記語句問題/2026-08-25.md#q4)

**復習の要点**: IDや属性、要求時の状況に基づいて、リソース・操作ごとに許可を判断する。ネットワーク上の場所だけで信用しない。

- 関連する新語: `ゼロトラスト原則` — 内外のネットワーク位置を信頼の根拠にせず、利用者・端末・要求文脈を継続的に検証する考え方。

#### CSRと証明書発行 — 70点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q5](../../学習記録/暗記語句問題/2026-08-25.md#q5)

**復習の要点**: CSRには公開鍵・SANなどを入れてCAへ送り、秘密鍵は申請者が保持する。CAは所有確認などを行い、公開鍵を含む証明書を発行する。

- 流れ図: [サーバ証明書の発行](../流れ図/サーバ証明書の発行.md)
- 関連する新語: `証明書チェーン検証` — サーバ証明書から中間CAをたどり、信頼済みルートCAまでの署名連鎖などを検証する処理。

#### MTA-STS / TLS-RPT — 70点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q8](../../学習記録/暗記語句問題/2026-08-25.md#q8)

**復習の要点**: MTA-STSは受信MXへのTLS接続と有効な証明書検証を要求するポリシー、TLS-RPTは接続やポリシー適用の失敗を報告する仕組みである。

- 関連する新語: `SMTPリレーとSTARTTLS` — SMTPリレーはメールを次のMTAへ中継し、STARTTLSは平文接続をTLSで保護する接続へ切り替える拡張である。

#### 鍵管理とローテーション — 70点

- [ ] 復習済み

出典: [2026-08-25 / Session 2 / Q13](../../学習記録/暗記語句問題/2026-08-25.md#q13)

**復習の要点**: 鍵管理は生成・保管・利用・失効・廃棄を管理し、ローテーションは漏えい時や定期更新時に旧鍵から新鍵へ安全に切り替える運用である。

- 関連する新語: `秘密鍵保護（HSM）` — HSMは秘密鍵を耐タンパ性のある専用機器内で保護し、取り出しにくくして署名や暗号処理に使う。
