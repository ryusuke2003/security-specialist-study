## 暗記語句問題

### 最優先

- 2026-08-17 / Session 1 / Q6 `EDRテレメトリ`（55 / 100）
  - 解説: EDRテレメトリは、端末から継続収集するプロセスツリー、コマンドライン、ファイル、ハッシュ、通信先などの行動データである。検知済みログの集約物ではなく、検知・調査・隔離の材料である。
  - 次に確認する点: 端末上のプロセス・通信・ファイルの行動記録を集めるものと説明する。
  - 関連する新語: `SIEM相関分析` — 複数の機器・サービスのログを時刻、利用者、端末などで結び付け、単一ログでは見えない攻撃を検知・調査すること。

- 2026-08-17 / Session 1 / Q7 `CVE / CWE`（40 / 100）
  - 解説: CVEは公開された個別の脆弱性を識別する番号であり、CWEは脆弱性につながるソフトウェア上の弱点の種類を分類する一覧である。CWEは攻撃対象の分類ではない。
  - 次に確認する点: CVE＝個別事例、CWE＝弱点分類、CVSS＝技術的深刻度と対比する。
  - 関連する新語: `静的解析 / 動的解析` — 静的解析はソースコードを実行せずに弱点候補を調べ、動的解析は実行中の挙動を観測して脆弱性を検出する手法である。

- 2026-08-17 / Session 1 / Q11 `ホスト名検証とSAN`（55 / 100）
  - 解説: TLSでは、接続先のホスト名がサーバ証明書のSANに含まれるかを確認する。SANは証明書が有効なDNS名・IPアドレスを列挙する拡張で、Subject名だけで判断しない。
  - 次に確認する点: 接続先名とSANを照合する目的を一文で説明する。
  - 関連する新語: `TLSハンドシェイク` — TLS接続時に鍵共有と証明書検証を行い、相手を認証して通信鍵を確立する手順である。
  - 流れ図: [TLS 1.3ハンドシェイク](../../流れ図/TLS1.3ハンドシェイク.md)

- 2026-08-17 / Session 1 / Q12 `ディスクイメージとハッシュ`（30 / 100）
  - 解説: ディスクイメージは対象ディスクをビット単位で複製した調査用の証拠である。取得元と複製したイメージのハッシュを照合し、証拠が改ざんされていないことを確認する。
  - 次に確認する点: ディスクイメージ＝複製、ハッシュ＝完全性確認と役割を分ける。
  - 関連する新語: `デジタルフォレンジック手順` — インシデントの証拠を保全し、取得、解析、報告を再現可能な手順で行う活動である。

- 2026-08-17 / Session 1 / Q13 `メールヘッダ解析`（0 / 100）
  - 解説: メールヘッダ解析では、Receivedから配送経路を確認し、Return-PathとAuthentication-Resultsからenvelope-fromやSPF・DKIM・DMARCの検証結果を読む。表示上のFromだけで送信元を判断しない。
  - 次に確認する点: Received、Return-Path、Authentication-Resultsの役割を対応付ける。
  - 関連する新語: `DKIM` — 送信側がメールの選んだヘッダと本文に電子署名を付け、受信側がDNS上の公開鍵で改ざんや送信ドメインとの関係を検証する仕組みである。

- 2026-08-17 / Session 1 / Q14 `MTA-STS / TLS-RPT`（0 / 100）
  - 解説: MTA-STSは、受信側ドメインが送信側メールサーバにTLS利用と有効証明書を持つ宛先サーバを方針として公開し、平文や偽証明書へのダウングレードを防ぎやすくする仕組みである。TLS-RPTはTLS接続の失敗報告を受け取る仕組みである。
  - 次に確認する点: MTA-STS＝TLS強制方針、TLS-RPT＝失敗レポートと対にする。
  - 関連する新語: `SMTPリレーとSTARTTLS` — SMTPリレーはメールサーバ間でメールを転送すること、STARTTLSは平文で始めたSMTP接続をTLSで保護する接続へ切り替える仕組みである。

- 2026-08-17 / Session 1 / Q15 `SAML`（0 / 100）
  - 解説: SAMLは、IdPが認証した利用者のAssertionをSPへ渡し、複数サービスへのSSOを実現するXMLベースの認証連携標準である。SPはAssertionの署名、発行者、宛先などを検証する。
  - 次に確認する点: IdPが認証し、SPがAssertionを検証する流れを覚える。
  - 関連する新語: `OAuth 2.0 / OIDC` — OAuth 2.0の認可とOIDCの認証を組み合わせ、外部IdPを使ったログイン連携を実現する標準である。
  - 流れ図: [SAMLによるSSO](../../流れ図/SAMLによるSSO.md)

- 2026-08-17 / Session 1 / Q16 `SSRF`（0 / 100）
  - 解説: SSRFは、Webアプリなどのサーバに攻撃者指定のURLへリクエストを送らせ、内部サービスやクラウドのメタデータサービスへアクセスさせる攻撃である。攻撃者のブラウザが直接アクセスするのではない。
  - 次に確認する点: サーバ側から内部へ送らせる攻撃経路を説明する。
  - 関連する新語: `クラウドIAMと一時資格情報` — クラウドではロールにより一時的な資格情報を発行し、長期秘密鍵を置かずに最小権限でアクセスさせる仕組みである。

- 2026-08-17 / Session 1 / Q17 `ハッシュとMAC`（30 / 100）
  - 解説: ハッシュはデータから一定長の値を計算して変更を検知する仕組みであり、MACは共有秘密鍵を使って計算する認証子である。MACは完全性に加え、鍵を持つ相手が作ったことの確認にも使える。
  - 次に確認する点: ハッシュは鍵なし、MACは共有秘密鍵ありと区別する。
  - 関連する新語: `パスワードハッシュ` — パスワードを復元可能な形で保存せず、saltを加えた計算コストの高いハッシュ値として保存・照合する仕組みである。

- 2026-08-17 / Session 1 / Q18 `電子署名`（25 / 100）
  - 解説: 電子署名は、送信者がデータのハッシュ値に秘密鍵で署名し、受信者が対応する公開鍵で検証する仕組みである。真正性と完全性を確認し、否認防止の根拠にもなる。
  - 次に確認する点: 秘密鍵で署名を作り、公開鍵で検証する向きを覚える。
  - 関連する新語: `コード署名と成果物署名` — ソフトウェアやビルド成果物に署名を付け、配布元と改ざんの有無を検証できるようにする仕組みである。

- 2026-08-17 / Session 1 / Q19 `CSRと証明書発行`（0 / 100）
  - 解説: CSRは、申請者が公開鍵、組織情報、SANなどを含めてCAへ送る証明書発行要求である。対応する秘密鍵は申請者側で保持し、CAは所有確認などをして証明書を発行する。
  - 次に確認する点: CSRには公開鍵を入れ、秘密鍵は外へ出さない。
  - 関連する新語: `証明書透明性（CT）` — CAが発行した証明書を公開ログへ記録し、第三者が誤発行を検出しやすくする仕組みである。

- 2026-08-17 / Session 1 / Q20 `ISMSとリスクアセスメント`（60 / 100）
  - 解説: ISMSは、方針、責任、管理策、運用、監査、改善を通じて情報セキュリティリスクを継続的に管理する仕組みである。リスクアセスメントは資産・脅威・脆弱性・影響などからリスクを特定、分析、評価する活動である。
  - 次に確認する点: ISMS＝継続的な管理、リスクアセスメント＝評価活動と分ける。
  - 関連する新語: `情報セキュリティ方針と規程` — 組織の情報セキュリティに関する目的と原則を方針として定め、具体的な遵守事項を規程・手順へ展開する管理文書体系である。

### 確認

- 2026-08-17 / Session 1 / Q1 `Windows AD / Kerberos`（75 / 100）
  - 解説: Active Directoryは利用者・端末・グループなどをWindowsドメインで一元管理するディレクトリサービスである。KerberosはTGTとサービス用チケットを用い、パスワードを各サービスへ繰り返し送らずに認証する方式である。
  - 次に確認する点: ADは管理基盤、Kerberosはチケット認証方式と分ける。
  - 関連する新語: `多要素認証` — 知識・所持・生体など異なる認証要素を組み合わせ、パスワード漏えいだけでの不正利用を防ぐ認証方式である。

- 2026-08-17 / Session 1 / Q4 `脆弱性例外管理`（85 / 100）
  - 解説: 修正できない脆弱性を例外にする場合でも、リスクを評価し、代替対策、責任者の承認、期限、再評価日を記録して一時的に受容する。無期限の放置ではない。
  - 次に確認する点: 例外には代替対策・承認・期限・再評価が必要である。
  - 関連する新語: `脆弱性管理ライフサイクル` — 資産把握、脆弱性の発見、優先順位付け、修正、例外管理、再確認を継続的に回す管理プロセスである。

- 2026-08-17 / Session 1 / Q8 `資産管理と攻撃面管理`（85 / 100）
  - 解説: 資産管理はサーバ、端末、クラウド、ソフトウェア、公開Webサイトなどを把握する活動である。攻撃面管理は、外部から到達できる資産や露出した弱点を継続的に発見・管理する活動である。
  - 次に確認する点: inventoryは資産一覧、ASMは外部に露出した攻撃入口の継続把握と区別する。
  - 関連する新語: `パッチ適用と検証` — パッチを本番適用する前後に機能と影響を確認し、必要に応じてロールバックや再スキャンを行う管理プロセスである。
