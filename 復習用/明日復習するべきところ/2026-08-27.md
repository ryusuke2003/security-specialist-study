# 2026-08-27に復習するべきところ

採点日: 2026-08-26

#### DNSキャッシュポイズニング — 0点

- [x] 復習済み

出典: [2026-08-25 / Session 1 / Q2](../../学習記録/10分復習/2026-08-25.md#q2)

**復習の要点**: DNSキャッシュポイズニング対策では、再帰DNSサーバが問合せごとにTXIDと送信元ポートをランダム化し、受け取った応答との一致を確認する。TTLが短いことだけでは正当なDNS応答か判断できない。

- 関連する新語: `DNSSEC` — DNS応答が正当なゾーンの秘密鍵で署名され、改ざんされていないことを検証する仕組み。

#### OAuth 2.0 / OIDC — 0点

- [x] 復習済み

出典: [2026-08-25 / Session 1 / Q8](../../学習記録/10分復習/2026-08-25.md#q8)

**復習の要点**: PKCEでは、認可要求時に`code_challenge`を送り、Token Endpointで認可コードと`code_verifier`を照合する。認可コードだけを横取りした攻撃者は、対応する`code_verifier`を知らないためトークンへ交換できない。SPAの長期`client_secret`は安全に隠せない。

- 流れ図: [OAuth 2.0 / OIDCの認可コードとPKCE](../流れ図/OAuth2とOIDCの認可コードとPKCE.md)
- 関連する新語: `認証と認可の分離` — 利用者が誰かを確認する認証と、何を許可するかを決める認可を別の関心事として扱う考え方。

#### DKIM — 35点

- [ ] 復習済み

出典: [2026-08-23 / Session 2 / Q2](../../学習記録/理解・応用問題/2026-08-23.md#q2)

**復習の要点**: DKIMは本文と選択ヘッダを暗号化する仕組みではなく、送信側が秘密鍵で署名し、受信側がDNSの`<s>._domainkey.<d>` TXTレコードから得た公開鍵で検証する仕組みである。`d=`は署名ドメイン、`s=`は公開鍵を選ぶselectorである。

- 流れ図: [DKIMの署名と検証](../流れ図/DKIMの署名と検証.md)
- 関連する新語: `DMARC` — SPFまたはDKIMの認証済みドメインと表示上のFromドメインのalignmentを確認し、メールの扱いを定める仕組み。

#### SAML — 55点

- [ ] 復習済み

出典: [2026-08-23 / Session 2 / Q5](../../学習記録/理解・応用問題/2026-08-23.md#q5)

**復習の要点**: SPはAssertionの署名・発行者・宛先・対象者・有効期限を確認する。SAMLは主にWeb SSOの認証連携、OAuth 2.0はAPI権限委譲の認可、OIDCはOAuth 2.0上の認証である。

- 流れ図: [SAMLによるSSO](../流れ図/SAMLによるSSO.md)
- 関連する新語: `OAuth 2.0 / OIDC` — OAuth 2.0はAPIアクセス権限の認可、OIDCはIDトークンで利用者を確認する認証仕様。

#### ハッシュとMAC — 65点

- [ ] 復習済み

出典: [2026-08-23 / Session 2 / Q6](../../学習記録/理解・応用問題/2026-08-23.md#q6)

**復習の要点**: 攻撃者が本文と値を一緒に差し替えられるWebhookでは、鍵なしハッシュは攻撃者も再計算できるため完全性を保証できない。共有秘密から作るHMACを検証し、失敗時は処理せず拒否・記録する。

- 関連する新語: `電子署名` — 秘密鍵で署名を作成し、公開鍵で検証して改ざんと署名者を確認する仕組み。

#### DNSSEC — 75点

- [ ] 復習済み

出典: [2026-08-23 / Session 2 / Q1](../../学習記録/理解・応用問題/2026-08-23.md#q1)

**復習の要点**: DSは親ゾーンに置く子ゾーンの特定DNSKEYのダイジェストであり、親の署名検証済みDSと照合して子の鍵を信頼する。受信したRRset・RRSIG・DNSKEYを使って署名検証し、DNS応答の真正性・完全性を確認する。

- 流れ図: [DNSSEC](../流れ図/DNSSEC.md)
- 関連する新語: `DNSキャッシュポイズニング` — 偽の名前解決結果をキャッシュDNSサーバへ保存させ、利用者を攻撃者の宛先へ誘導する攻撃。

#### VPN（IPsec） — 75点

- [ ] 復習済み

出典: [2026-08-23 / Session 2 / Q3](../../学習記録/理解・応用問題/2026-08-23.md#q3)

**復習の要点**: IKEが相互認証・鍵導出・暗号方式の交渉・SA確立を行い、ESPがそのSAで実データを保護する。拠点間のトンネルモードでは元IPヘッダを含む元IPパケット全体を内側に包み、外側IPヘッダで相手VPNゲートウェイへ届ける。

- 流れ図: [IPsecトンネルモードとIKE](../流れ図/IPsecトンネルモードとIKE.md)
- 関連する新語: `ネットワークセグメンテーション` — VLANやACLなどでネットワークを区画化し、不要な到達性や横展開を抑える考え方。

#### ホスト名検証とSAN — 90点

- [ ] 復習済み

出典: [2026-08-23 / Session 2 / Q4](../../学習記録/理解・応用問題/2026-08-23.md#q4)

**復習の要点**: SANがある証明書ではSANと接続先名を照合する。`*.example.jp`のようなワイルドカードは通常、左端の1ラベルだけに一致し、`a.b.example.jp`のような複数階層には一致しない。

- 関連する新語: `OCSP stapling` — サーバがCAから得たOCSP応答をTLSハンドシェイクで提示し、クライアントの失効照会負荷とプライバシー上の懸念を抑える方式。
