# 流れ図の監査と測定

対象は`復習用/流れ図/`の全23資料。比較基準はPR #12を取り込んだ`5e1cded662aba1992174aa50df8a4039aa84461c`で、この23資料はその前の`3c73e677491883494ac05aede12faa296e403502`から変更されていない。ファイル名は維持し、既存の復習ノートからの参照を保った。

## 変更内容

各資料に「前提と登場人物」「処理後に残るもの」「注意点」「参照資料」を設けた。通信・利用者操作・内部処理の主体を明記し、登録と認証、鍵交換とデータ通信、侵害対応と復旧など目的の違う段階を分けた。参照資料はRFC・W3C・FIDO・OWASP・Microsoft・CISA等の一次資料を各テーマに付けている。

特に次の混同を避けるようにした。

- WebAuthn：RPはサービス側、ブラウザ・認証器は利用者側。challenge、clientDataJSON、署名、検証、通常アクセスのCookieを区別する。
- CORS／CSRF：ブラウザによる送信・読取り制御と、サーバによる認証・認可・CSRFトークン検証を区別する。送信後の読取り拒否を処理の取消と描かない。
- Kerberos／SAML／OIDC：チケット・Assertion・IDトークンの検証と、サービス自身のセッション・認可を区別する。
- TLS／AEAD／署名：計算の依存関係とネットワーク送信、秘密鍵と共有鍵、署名検証と復号を混ぜない。タグ検証に成功する前の平文をアプリへ渡さない。
- EDR／ランサムウェア対応：分析・指示・実行・確認の担当者を分け、コマンド送信を隔離成功と同一視しない。

## 検証条件

Pythonの全101テストに成功した。変更前29図、変更後42図は、いずれもMermaid 11.12.2で全件描画に成功した。旧図に構文エラーがあったという主張ではない。描画後は一覧画像と個別画像で配置・矢印・文字の折り返しを確認した。

描画環境はChromium 144.0.7559.96、Noto Sans CJK JP。`mermaid.initialize`に`startOnLoad: false`、`securityLevel: strict`、`theme: default`、`sequence.useMaxWidth: false`、`flowchart.useMaxWidth: false`を指定し、各ブロックを`mermaid.render`へ渡した。幅はSVGを左右16pxの同一余白で囲んだ画像の幅である。GitHubの表示幅・フォント・Mermaid版が異なれば数値は変わる。

構造テストの再実行方法は[開発・テスト](開発・テスト.md)、資料の入口は[流れ図ガイド](流れ図ガイド.md)を参照する。構造テストだけでMermaid構文・プロトコルの正しさを保証しないため、今後も変更した図は実際に描画する。

## 変更しないものと後片付け

学習記録・理解度・カタログ・日付別復習チェックリスト・出題採点ロジックは変更しない。既存23ファイルを改訂し、旧版や重複図ファイルを残さない。検証に使った画像、アーカイブ、ブラウザ用Mermaid、Pythonキャッシュはコミットしない。一時的なCIのスナップショット／レンダラー取得処理は最終差分から取り除き、既存のPythonテストCIへ戻す。
