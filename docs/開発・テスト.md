# 開発・テスト

## 補助コマンド

通常問題の候補計画を確認するには、次を実行します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date YYYY-MM-DD
```

暗記語句問題では、モードと問題数を指定します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date YYYY-MM-DD --mode term-recall --count 10
```

今日の10分復習の候補計画は、次で確認します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date YYYY-MM-DD --mode quick-review
```

問題作成・採点の開始時に、当日分の10分復習が作成済みかを次で確認します。`exists` は自動作成不要、`missing` は作成対象を表します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py quick-review-status \
  --root . --date YYYY-MM-DD
```

未回答問題に割り当て済みの語句は通常の計画から除外されます。未回答問題の復習を明示的に計画するときだけ、`--include-unanswered`を追加します。

10分復習は、選択肢のMarkdownチェックボックスが一つだけ選ばれていると回答済みになります。未チェックまたは複数チェックの問題は、未解答一覧に残ります。

採点済みSessionは `record` でprogressへ反映します。

- 理解・応用問題: `--mode standard`
- 暗記語句問題: `--mode term-recall`
- 10分復習: `--mode quick-review`（Sessionを完了にするだけで進捗は更新しない）

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py record \
  --root . --date YYYY-MM-DD --session N --mode standard
```

詳しい前提条件と失敗時の扱いは、[セッション形式](../参照資料/セッション形式.md)を参照してください。

全回答済みSessionを古い順に採点した結果、すでに後の日付の進捗が記録済みで`record`が時系列保護により停止することがあります。

その場合は、次でprogressを再構築します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py rebuild --root .
```

未解答一覧を確認・更新するには、次を実行します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py unanswered --root .
```

採点済みSessionの当日分を行ったことログへ追記・再生成するには、次を実行します。採点時にも自動更新され、判定には各Sessionの`Graded`日を使います。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py activity-log \
  --root . --date YYYY-MM-DD
```

未復習一覧を確認・更新するには、次を実行します。日付別の復習ノートで未チェックの項目だけを、リンク一覧として再生成します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py unreviewed --root .
```

## ローカルテスト

補助ロジックとSkill構造の回帰テストは、標準ライブラリだけで実行できます。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s skills/security-specialist-trainer/tests -v
```

テストファイル名の必須接頭辞 `test_` より後ろ、テストクラス名、`test_` で始まるテストメソッド名は、ローカルおよびCIのログから確認内容が分かるよう日本語で記述します。

新しいテストでも、この命名規則を維持します。

## 継続的インテグレーション

GitHub Actionsは、ブランチ名にかかわらずすべての `push` で同じテストをPython 3.14上で実行します。

設定は `.github/workflows/python-tests.yml` にあります。

## 文書変更時の確認

READMEから詳細を移動するときは、情報を削除せず適切な `docs/` 文書へ移し、ルートREADMEから到達できるようにします。

実装上の厳密な制約は `参照資料/` を正本とし、概要文書と矛盾させません。

相対リンクは移動先を基準に更新し、テストで主要文書の存在とREADMEからの参照を確認します。
