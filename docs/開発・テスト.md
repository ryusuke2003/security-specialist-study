# 開発・テスト

## 補助コマンド

通常問題の作問ブリーフィングを確認するには、次を実行します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py briefing \
  --root . --date YYYY-MM-DD
```

暗記語句問題では、モードと問題数を指定します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py briefing \
  --root . --date YYYY-MM-DD --mode term-recall --count 10
```

今日の10分復習の候補計画は、次で確認します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py briefing \
  --root . --date YYYY-MM-DD --mode quick-review
```

問題作成・採点の開始時に、当日分の10分復習が作成済みかを次で確認します。`exists` は自動作成不要、`missing` は作成対象を表します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py quick-review-status \
  --root . --date YYYY-MM-DD
```

問題作成後は、回答を始める前に対象Sessionを検証します。`--mode`には理解・応用問題なら`standard`、暗記語句なら`term-recall`、10分復習なら`quick-review`を指定します。この検証は作成直後専用で、Status、標準プレースホルダーと完全一致する回答欄、全て未チェックのA/B/Cと固定の`D. わかりません`、採点ブロックの不在も確認します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py validate-session \
  --root . --date YYYY-MM-DD --session N --mode standard
```

未回答問題に割り当て済みの語句は通常の計画から除外されます。未回答問題の復習を明示的に計画するときだけ、`--include-unanswered`を追加します。

10分復習は、A/B/C/DのMarkdownチェックボックスが一つだけ選ばれていると回答済みになります。Dだけを選んだ場合も回答済みで0点となり、未チェックまたは複数チェックの問題は未解答一覧に残ります。

採点済みSessionは `record` でprogressへ反映します。処理完了時に未解答一覧も再生成されます。

- 理解・応用問題: `--mode standard`
- 暗記語句問題: `--mode term-recall`
- 10分復習: `--mode quick-review`（Sessionを完了にするだけで進捗は更新しない）

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py record \
  --root . --date YYYY-MM-DD --session N --mode standard
```

詳しい前提条件と失敗時の扱いは、[セッション形式](../参照資料/セッション形式.md)を参照してください。

全回答済みSessionを古い順に採点した結果、すでに後の日付の進捗が記録済みで`record`が時系列保護により停止することがあります。

その場合は、次でprogressを再構築します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py rebuild --root .
```

未解答一覧を確認・更新するには、次を実行します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py unanswered --root .
```

採点済みSessionの当日分を行ったことログへ追記・再生成するには、次を実行します。採点時にも自動更新され、判定には各Sessionの`Graded`日を使います。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py activity-log \
  --root . --date YYYY-MM-DD
```

未復習一覧を確認・更新するには、次を実行します。日付別の復習ノートで未チェックの項目だけを、チェック欄のラベルに依存せずリンク一覧として再生成します。採点時は、実際の採点日の翌日分の復習ノートを作成・更新した後に実行し、今回追加した項目が一覧へ載ったことまで確認します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py unreviewed --root .
```

## ローカルテスト

補助ロジックとSkill構造の回帰テストは、標準ライブラリだけで実行できます。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s skills/security-specialist-trainer/tests -v
```

テストファイル名の必須接頭辞 `test_` より後ろ、テストクラス名、`test_` で始まるテストメソッド名は、ローカルおよびCIのログから確認内容が分かるよう日本語で記述します。

新しいテストでも、この命名規則を維持します。

## 流れ図の検証

[流れ図ガイド](流れ図ガイド.md)と[作成ルール](../skills/security-specialist-trainer/references/流れ図作成ルール.md)を参照します。流れ図の構造だけを確認するには、次を実行します。通常の全件テストにも含まれます。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s skills/security-specialist-trainer/tests -p 'test_流れ図.py' -v
```

この検査は必須節、登場人物ID、主語の目印、操作番号、相対リンク、ガイドの網羅性を確認します。日本語の意味解析やMermaidの完全な構文検証ではありません。変更した全Mermaidブロックを実際に描画し、矢印・分岐・ラベルの読みやすさと、一次資料に照らした技術内容を別に確認してください。

描画に使用したMermaidの版と結果を変更記録へ残します。検証用のSVG・PNG・HTML・依存パッケージはリポジトリへ追加しません。監査例と測定条件は[流れ図監査と測定](流れ図監査と測定.md)に記録しています。

## 補助スクリプトの構成

`scripts/study_helper.py`は既存コマンドとPython APIを保つ互換入口です。公開名は`trainer.__all__`で明示的に固定し、互換入口も同じ一覧だけを再公開します。実装は`scripts/trainer/`へ責務別に分けます。

- `common.py`: 定数、データモデル、パス、Markdown表、得点計算の共通部品
- `session_parser.py`: Session探索、Mode解決、採点済み解析、作成直後の検証
- `indexes.py`: 未解答・未復習・活動・モチベーションの生成ビュー
- `progress.py`: 理解度・履歴更新、Session確定、時系列再構築
- `planner.py`: 候補順位付け、出題配分、planとbriefingの表示
- `cli.py`: 引数解析とサブコマンド実行

モジュール間の依存は、共通部品からSession解析・索引・進捗へ向かう一方向を基本とし、CLIだけが全機能を組み合わせます。既存利用者とテストは引き続き`study_helper.py`を呼び出します。

一覧更新の契約は、文字列の存在確認だけでなく統合テストで検証します。生成時に未解答一覧へ載った問題が`record`後に消え、作成した翌日復習ノートが`unreviewed`後に未復習一覧へ載るところまでを一連で確認します。さらに、全CLIサブコマンドの実行分岐、責務別モジュールの未解決グローバル参照、公開APIの一致、Markdownリンクの解決、文書化されたCLIの引数解析、`record`失敗時に対象ファイル全体が実行前の状態へ戻ることも自動検証します。文書の意思決定契約に必要な最小限を除き、構造テストで個別文言を大量に照合しません。

## 継続的インテグレーション

GitHub Actionsは、ブランチ名にかかわらずすべての `push` で同じテストをPython 3.14上で実行します。

設定は `.github/workflows/python-tests.yml` にあります。
