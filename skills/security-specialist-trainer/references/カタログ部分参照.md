# カタログ部分参照

日常の問題作成では、`参照資料/出題分類と概念カタログ.md` を全読みにしない。`study_helper.py briefing` が進捗、忘却期限、重要度、分野配分、直近出題と重複抑制を集約するため、作問時に必要なのは採用候補の周辺だけである。

## 日常の出題

1. `briefing` の候補と注意から、実際に出題するPrimary Termを仮決定する。
2. 各候補のカタログ行だけを固定文字列検索で確認する。たとえばDNSSECなら、次のように検索する。

   ```bash
   rg -n -F -- '| DNSSEC |' 参照資料/出題分類と概念カタログ.md
   ```

3. その行のDomain、Track、Importance、Entry Level、Related、Prerequisitesを確認する。Relatedにある概念を問題へ使う、または前提の不足が疑われる場合だけ、その概念の行も同様に検索する。
4. 前提は候補語の**直接のPrerequisitesだけ**を確認する。さらにその前提の前提へ再帰的に広げない。候補と直接前提の理解度が低い場合は、前提を組み合わせるか問題のLevelを下げる。

`Related` と `Prerequisites` は `/` 区切りだが、カタログのTerm自体にも `/` を含むことがある。分割結果を機械的にTerm名とみなさず、カタログに同じ正式名称の行がある場合だけ追加参照する。行がない関連語は、候補行に書かれた文脈として扱う。

日常作業で確認するのは、原則として採用候補、問題に使う関連語、必要な直接前提の行だけである。`briefing` の候補を無作為な語句へ置き換えず、候補行を確認した結果で問題文の条件・関連語・難易度を調整する。

## 全読みに戻す場合

次の場合だけ、概念カタログ全体を読む。

- 利用者が明示的にカタログ拡張・整理、または過去問を踏まえた見直しを依頼したとき
- 分野指定なしで幅広く出題し、全分野の配分や診断構成を判断するとき
- 前提関係、正式名称、重複・矛盾を調査するとき
- 継続的な分野偏りやカタログ全体の出題方針を監査するとき

これら以外では、全読みによって無関係な分野を作問コンテキストへ入れない。全体の分野配分、期限、直近出題、重複警告は`briefing`の出力を基準に確認する。
