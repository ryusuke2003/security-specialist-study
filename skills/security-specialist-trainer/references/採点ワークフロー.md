# 通常・暗記語句の採点ワークフロー

通常・暗記語句Sessionの採点でAIが実際に行う操作だけを定める。進捗スコア、復習間隔、候補優先度などの計算はCLIへ任せ、採点時に計算式を読み込んだり手計算したりしない。10分復習は[10分復習採点ワークフロー.md](10分復習採点ワークフロー.md)を使う。

## 1. 採点対象を特定する

採点前に[共通開始処理.md](共通開始処理.md)を一度だけ完了し、次を実行する。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py grading-candidates --root .
```

- 出力された候補を作業対象とし、Git差分、コミット履歴で絞らない。
- 利用者が日付・Session番号を指定した場合はその対象を優先する。指定がなければ候補を日付・Session番号の昇順に処理し、一つを`record`してから次へ進む。
- 空欄を含むSessionは採点せず、未回答のQ番号を伝える。`わかりません`など明示的な解答不能は回答済みとして扱い、`0 / 100`で採点する。
- Session探索、現行・旧保存先の互換、形式エラーの判定は`grading-candidates`と`record`へ任せる。AI側で探索条件やパーサ規則を再実装しない。

## 2. 回答を意味ベースで採点する

### 理解・応用問題

まず**模範解答を見る前に、問題文とシナリオから採点対象を2〜4個程度へ分解する**。何を比較するのか、何の情報・理由・対策を答えるのかを問題文の要求だけから決め、その観点へ100点を配分する。`Related Terms`や模範的な説明に含まれる補足事項を、暗黙の必須要件へ追加しない。

問題文が明示的に求めた観点だけを評価し、必要な観点の配点を100点へ正規化する。目安として次を使う。

| 観点 | 基本配点 | 評価する内容 |
|---|---:|---|
| 定義 | 15 | 何であるか、何でないか |
| 原理・目的 | 20 | なぜ成立・機能するか |
| 成立条件 | 15 | 必要条件、前提、境界条件 |
| シナリオ適用 | 20 | ログ・通信・設定からの推論、影響 |
| 対策と理由 | 20 | 対策が効く箇所、運用、迂回や限界 |
| 比較・限界 | 10 | 類似概念との差、残存リスク |

同義表現を認め、問題文で要求していない専門語や補足知識の不足では減点しない。要求された要点を意味的にすべて満たせば満点にする。因果の逆転、主体の取り違え、安全でない対策、明示された要点の欠落は減点する。

特に、問題文が「どのような情報を使うか」「例を挙げよ」のように幅を持つ要求をしている場合、正しいカテゴリや代表例を示せていれば大部分を与える。具体例が一つ不足していることを、模範解答に列挙された各例ごとの複数減点へ分解しない。また、継続的再評価、実装固有の状態値、追加の防御機構などを問題文が要求していなければ、それらが書かれていないことを減点理由にしない。

### 暗記語句問題

`term-recall`では、その語句を近接概念と区別するために必要な**最小限の定義要素**だけを0〜100点で評価する。目的、具体例、対策、長い説明がなくても、定義の核がそろっていれば満点にする。別概念との混同や必須要素の欠落は部分点または大きな減点にする。

### 採点ブロック

通常・暗記語句の各Qへ次を一つだけ追記し、採点中はSessionのStatusを`grading`にする。

```markdown
### 採点

Score: NN / 100

#### 良かった点

- <問題文に対して正しく説明できた点>

#### 足りない点・誤解

- <問題文で求められたが不足・誤っていた点>

#### 模範的な説明

<短い説明。原則150〜350字程度。>

#### 次回確認する観点

- <次に一つ確認する観点>
```

模範的な説明と補足は、セキスペ合格に必要な論点を優先し、正答に不要な規格の細部や実装依存の例外を網羅しない。追加知識が誤解防止や原理理解に明確に役立つ場合は補足してよいが、問題文で要求していなければ必須知識・減点対象・次回確認事項にはしない。

補足知識を参考として示す場合も、問題文で要求していなければ「足りない点・誤解」や「次回確認する観点」へ混ぜない。模範的な説明は採点後の学習用説明であり、その文章に含まれる要素を逆算して採点基準にしない。

## 3. `record`で進捗を反映する

全問の採点ブロックを作成したら、対象を明示して実行する。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py record \
  --root . --date YYYY-MM-DD --session N --mode standard|term-recall
```

- `record`に、理解度、モード別Score、Attempts、復習日、分野理解度、学習履歴、活動ログ、モチベーション、未解答一覧、Session確定を任せる。AIはこれらの計算式を手計算して書き換えない。
- `record`が失敗したら、表示された原因を直して再実行する。`graded`を手作業で設定しない。
- 古いSessionを後から反映する必要があり`record`が時系列再構築を求めた場合だけ、次を使う。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py rebuild --root .
```

実装内部のrollback、旧パス互換、表パーサの異常系はCLIの責務であり、このワークフローでは展開しない。

`record`成功後は、対象Sessionが`graded`になり、問題別点数とSession Summaryが存在すること、対象Primary Termsが進捗へ一度だけ反映されたことを確認する。

## 4. 復習メモを作る

採点で新たな学びが残る場合だけ行う。共通開始処理で取得した学習日を**採点日**として使い、Sessionのファイル名や`Created`から逆算しない。

- 再利用可能な文章説明は、`復習用/学んだこと/README.md`と最も近い分野ファイルを確認し、重複しない内容だけ同日の`## YYYY-MM-DD`へ追記する。新規分野ファイルを作る場合はREADMEも同時に更新する。
- 複数の主体、順序、分岐、信頼やデータの移動を追う必要がある場合だけ[流れ図作成ルール.md](流れ図作成ルール.md)を使う。単純な定義だけなら図を作らない。
- 通常・暗記語句の`Score < 100`を、採点日の翌学習日の`復習用/明日復習するべきところ/YYYY-MM-DD.md`へ集約する。同じSession/Qの再処理では既存項目を更新し、他Sessionの項目を消さない。
- 各項目は見出し直下の`- [ ] 復習済み`を正規形とし、点数、元Qへの正確な相対リンク、復習の要点、関連する新語を含める。

復習ノートの更新後に次を実行する。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py unreviewed --root .
```

今回追加した未チェック項目が`復習用/未復習一覧.md`へ掲載されたことを確認する。追加したはずの項目が欠けている場合は完了扱いにしない。

## 5. 最終確認

利用者へ完了を返す前に、次だけ確認する。

1. 採点対象の全Qに有効な点数がある。
2. `record`が成功し、Sessionが`graded`である。
3. Primary Termsだけが数値進捗へ反映され、Related Termsを直接更新していない。
4. 必要な学習メモと翌日復習ノートを作成した。
5. `unreviewed`後の未復習一覧に今回の対象が反映されている。

数値理解度や復習日の算出理由を利用者から明示的に聞かれた場合だけ、[進捗計算仕様.md](../../../参照資料/進捗計算仕様.md)を参照する。通常の採点では読まない。
