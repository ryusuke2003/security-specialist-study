# 通常・暗記語句の採点ワークフロー

採点対象を探す前に[共通開始処理.md](共通開始処理.md)を完了する。通常・暗記語句のSessionはこのファイル、10分復習は[10分復習採点ワークフロー.md](10分復習採点ワークフロー.md)を使う。

## 採点前チェック

1. 問題文を読む前に `python3 skills/security-specialist-trainer/scripts/study_helper.py grading-candidates --root .` を実行する。出力全件を作業対象とし、見た目の `Status`、Git差分、コミット履歴で絞らない。
2. 次の全保存先を調べる: 現行の `学習記録/理解・応用問題/`、`学習記録/暗記語句問題/`、`学習記録/10分復習/`、旧 `学習記録/standard/`、`学習記録/term-recall/`、直下の `学習記録/YYYY-MM-DD.md`。HTMLの回答プレースホルダは空欄として扱う。全問回答済みで、採点ブロックまたはProgress更新が欠けるSessionだけが候補である。利用者指定の `cancelled` は除外する。
3. 日付・Session番号の指定がなければ、候補全件を日付、Session番号の昇順に採点する。未回答Sessionは未回答のQ番号を伝えるが、他の採点を妨げない。重複するPrimary Termの進捗を正しく更新するため、前のSessionの記録を終えてから次を処理する。
4. `わかりません` は回答済みの `0 / 100` とする。10分復習が作業対象に含まれる場合は、専用ワークフローで採点してから時系列順の処理へ戻る。

## 採点・記録

各問題のメタデータ・回答を読み、意味内容で採点する。通常問題は問題文が求めた観点だけを100点へ正規化し、未要求の補足知識を理由に減点しない。暗記語句問題は近接概念と区別する最小限の定義要素だけを評価する。各回答には既存ブロックを置換して、点数、良かった点、足りない点・誤解、短い模範的な説明、次回確認する観点を記す。SessionのStatusはこの時点で `grading` にする。

通常・暗記語句の各Qには次の採点ブロックを一つ置く。

```markdown
### 採点

Score: NN / 100

#### 良かった点

- <根拠>

#### 足りない点・誤解

- <根拠>

#### 模範的な説明

<短い説明>

#### 次回確認する観点

- <観点>
```

全問に有効な点数が付いた後、次を実行する。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py record \
  --root . --date YYYY-MM-DD --session N --mode standard|term-recall
```

暗記語句Sessionでは `--mode term-recall` を指定する。`--mode` は対象Sessionのモード検証に使い、省略時も日付・Session番号が一意なら自動解決する。新旧パスなど複数ファイルに同じ番号がある場合は、`Applied Sessions` のキー衝突を避けるため `--mode` の有無にかかわらず停止する。

現行日本語ディレクトリでは、`Mode`、問題数、Q1からの連番、ディレクトリとModeの組合せを満たす必要がある。`record` は、Question Countの必須性・一意性・1〜30の整数範囲、実際のQ見出し数との一致、Q番号がQ1から重複・欠番なしの連番であることも検証する。形式外のQ見出しを見落とさず拒否し、自動補正は行わない。暗記語句ではPrimary Term一つ、Level 1、Track A/Bの配分も検証される。

記録処理は、各理解度、学習履歴、活動ログ、モチベーション、未解答一覧を先に更新する。すべて成功した後にSession Summaryと `- Graded: YYYY-MM-DD` を追記し、Statusを `graded` にする。処理中に例外が発生した場合は、Session、理解度、学習履歴、活動ログ、モチベーション、未解答一覧を実行前の内容へ戻し、Statusを`grading`のまま保つ。原因修正後に`record`を再実行できる。このロールバックは同一プロセス内のエラーを対象とし、OS停止や強制終了に対するクラッシュセーフなトランザクションではない。未復習一覧は、この後で翌日復習ノートを作成してから更新する。Session末尾には次のSummaryを残す。

```markdown
## Session N Summary

- Average: NN / 100
- Strong points: <要約>
- Weak points: <要約>
- 次回復習: <目安>
- Progress updated: 語句別理解度.md / 分野別理解度.md / 学習履歴.md
```

採点日（JST午前5時切替）の全Sessionを `学習記録/行ったこと.md` へ追記する。日付の節は新しい順に並べ、過去の日付の記録は消さず、対象日を再処理した場合だけその日付の節を更新する。必要時には次で再生成できる。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py activity-log --root . --date YYYY-MM-DD
```

記録済みより古いSessionが原因で失敗したときは、対象を `grading` のままにして次で進捗を時系列再構築してから再試行する。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py rebuild --root .
```

それ以外の記録失敗では停止し、`graded` を手作業で設定しない。記録後はSessionと進捗3ファイルを読み直し、全問の点数、平均、重複のない語句・履歴行、次回復習日を確認する。

## 状態判定

- `awaiting_answers`: 新規作成時の初期値。後から全回答を記入しても残り得るため、採点可否の判定には使わない。
- `ready_for_grading`: 任意の目印。採点可否はこの値の有無ではなく、全回答が記入済みかで判断する。
- `grading`: 問題別採点は存在するが、Progress更新が途中または未確認。`record` を再実行して復旧できる。
- `graded`: 問題別採点とProgress更新が完了。
- `cancelled`: ユーザーが明示的に中止した場合だけ使う。

進捗更新まで完了したかは、各問の有効な採点ブロックと、Session Summaryの `Progress updated` で判定する。採点ブロックが途中まで存在する場合や、全問採点済みでもSession Summaryがない場合は、同じ時系列順で復旧処理する。

## 復習ノート作成

採点で新たな学びが残る場合にだけ実施する。

共通開始処理で取得した学習日をこの処理の**採点日**として保持する。翌学習日のファイル名はその採点日の翌日とし、Sessionのファイル名や`Created`から逆算しない。例えば、`2026-08-26`作成のSessionを`2026-09-03`に採点した場合、復習先は`2026-09-04.md`、見出し直下の採点日は`2026-09-03`である。

- 複数の主体・順序・分岐・信頼やデータの移動を扱うときだけ、`復習用/流れ図/` を全件確認して既存図を再利用する。新規図は `復習用/流れ図/<topic>.md` に置き、Mermaidで主体・受け手・対象を明示する。単純な定義には図を作らない。
- 再利用可能な説明は、`復習用/学んだこと/README.md` と最も近い `復習用/学んだこと/<分野>.md` を確認してから、当日の `## YYYY-MM-DD` の下へ重複なく追記する。新規分野を作るならREADMEにも追加する。
- 通常・暗記語句の `Score < 100` を翌学習日の `復習用/明日復習するべきところ/YYYY-MM-DD.md` に集約する。ファイル先頭は`# YYYY-MM-DDに復習するべきところ`と`採点日: YYYY-MM-DD`、各項目の状態は見出し直下の`- [ ] 復習済み`を正規形とし、文言を言い換えない。各項目は点数、出典、復習の要点、関連する新語を含め、点数・日付・Session・Q番号の順で並べる。出典は元Qへの正確な相対リンクとし、関連する新語は原則Importance 4以上のカタログ語句から選ぶ。
- 再処理では同じSession/Qの項目を更新し、他のSessionの項目は消さない。図を作った場合はMermaid構文も確認する。

すべての復習ノートを作成・更新した後に、未復習一覧を再生成する。これを採点処理の最後に行い、新しい翌日復習項目を一覧へ反映する。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py unreviewed --root .
```

コマンドの件数表示と`復習用/未復習一覧.md`を読み直し、今回追加した未チェック項目がすべて掲載されたことを確認する。追加直後なのに件数が0、または一項目でも欠ける場合は採点後処理の失敗として扱い、完了報告をしない。集計処理は見出し内の未チェック状態を正本として扱うため、過去のチェック欄に文言揺れがあっても未復習項目から除外しない。
