# 進捗計算仕様

この文書は、理解度・復習日・出題候補の**計算実装を変更、デバッグ、または説明するときだけ**参照する。

通常の問題作成は`briefing`の出力、通常の採点は`record`の結果を使うため、この文書を毎回読み込まない。

```text
通常の採点
→ 読まない。意味ベースで採点し、recordへ渡す

通常の問題作成
→ 読まない。briefingの候補・Suggested Level・理由を使う

「なぜこの理解度・復習日になった？」の説明
→ 必要な節だけ読む

計算ロジックの変更・不具合調査
→ この文書と対応するPython実装・テストを読む
```

## 正本

数値定数と境界値の正本はMarkdownではなく、`skills/security-specialist-trainer/scripts/trainer/`配下のPython実装とテストである。Markdownへ同じ閾値表や重みを複製しない。

主な責務は次のとおり。

- `common.py`
  - `target_level`: 理解度から出題Levelを決める
  - `level_cap`: 問題Levelごとの総合理解度へ入る証拠上限を返す
  - `blend_mastery`: 過去の理解度と今回の証拠を合成する
  - `updated_mastery`: 通常説明・総合理解度を更新する
  - `updated_recall_mastery`: Recall Scoreを更新する
  - `base_interval` / `next_interval`: 復習間隔を決める
- `planner.py`
  - `build_candidates`: 弱点、期限、未学習、関連、分野バランス、重要度、直近出題などから候補優先度を作る
  - `adaptive_plan`: 弱点・復習期・新規・発展などの枠へ候補を割り当てる
  - `quick_review_plan`: 10分復習の候補を選ぶ
- `progress.py`
  - `update_term_records`: Primary Termの総合・モード別理解度と復習日を更新する
  - `render_domains`: 語句理解度と直近の証拠から分野理解度を生成する
  - `record_progress` / `rebuild_progress`: Sessionから派生進捗を確定・再構築する

CLIの入口は`skills/security-specialist-trainer/scripts/study_helper.py`であり、通常運用では関数を直接呼ばず`briefing`、`record`、`rebuild`などのサブコマンドを使う。

## 語句理解度

通常問題の生点を`q`、問題Levelを`L`とすると、総合理解度へ入れる証拠は概念的に次の形になる。

```text
e = min(q, level_cap(L))
new_score = blend_mastery(old_score, attempts, e, q)
```

具体的なLevel上限、Attemptsごとの混合率、低得点時の補正値は`common.py`を正本とし、この文書には複製しない。

暗記語句では、語句想起能力そのものを表す`Recall Score`にはLevel 1の証拠上限を掛けず、総合Scoreへ取り込む証拠には通常のLevel上限を使う。通常問題は`Explanation Score`側を更新する。

`Primary Terms`だけが数値更新対象であり、`Related Terms`はNotesや次回候補の文脈には使ってもScore・Average・Attemptsを直接更新しない。

## 復習日

復習日は概念的に次で決める。

```text
interval = next_interval(current_mode_score, answer_score, level, stable_high_count)
next_review = study_date + interval
```

基礎間隔、低得点時の短縮、高難度の連続成功時の延長条件は`common.py`の`base_interval`と`next_interval`を正本とする。

RecallとExplanationは、それぞれ独立した最終学習日と次回復習日を持つ。共通の`Last Studied`は両モードの新しい方、共通の`Next Review`は設定済みのモード別期限の早い方を表示する。

## 出題Level・忘却度・候補優先度

通常の作問ではAIが数値を再計算せず、`briefing`が返す候補、理由、Suggested Levelを使う。

内部では、`target_level`がモード別理解度からLevelを決め、`build_candidates`が経過時間と`base_interval`から忘却度を求める。候補優先度には、自己モードの弱点、忘却、科目区分、未学習、弱い概念との関連、最近の分野バランス、利用者のfocus、Importance、直近出題抑制、別モードの弱点などが反映される。

各要素の具体的な係数や境界値は`planner.py`を正本とする。ドキュメントへ係数表を複製しない。

## 分野理解度

分野理解度は、所属語句の現在理解度と、その分野の最近の採点済み問題から得たLevel補正済み証拠を組み合わせて`progress.py`が生成する。

分野Level、Provisional判定、Coverage（未評価・用語想起のみ・応用まで確認・高難度で安定）などの具体的な判定値も実装とテストを正本とする。利用者へ現在値を説明するときは、まず`進捗/分野別理解度.md`に出力された結果を使い、境界値の根拠まで求められた場合だけ実装を確認する。

## quick-review

`quick-review`は短時間の想起確認であり、正答・誤答の結果から通常の数値理解度を直接更新しない。誤答や`D. わかりません`は復習候補として利用するが、Recall ScoreやExplanation Scoreの計算証拠にはしない。

具体的な候補選択は`planner.py`、採点後の反映は`record`の実装を正本とする。

## 変更時のルール

計算ロジックを変える場合は、次の順で扱う。

1. 対応するPython関数とテストを変更する。
2. 振る舞いが変わる場合だけ、この文書の概念説明を更新する。
3. `出題選定ルール.md`や`採点ワークフロー.md`には、AIが実行時に必要な判断だけを書く。数値定数をコピーしない。
4. 利用者向け文書は結果の意味と使い方を説明し、内部係数を正本として持たない。

Markdownと実装で具体値が食い違った場合、Python実装を現行動作の正本として扱い、同じ変更で古いMarkdownの記述を修正する。
