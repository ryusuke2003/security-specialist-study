# 10分復習Session形式

`Mode: quick-review` のSessionだけに適用する詳細形式である。保存先と共通メタデータは[セッション共通形式](セッション形式.md)を正本とする。

```markdown
# YYYY-MM-DD 10分復習

## Session N

- Created: YYYY-MM-DD
- Status: awaiting_answers
- Mode: quick-review
- Question Count: 8

### Q1

- Domain: <分野>
- Primary Terms:
  - `<主要語句>`
- Related Terms:
  - `<関連語句>`
- Level: <1-5>
- Track: <A|B>

### 問題

<問題文>

- [ ] A. <選択肢>
- [ ] B. <選択肢>
- [ ] C. <選択肢>
```

既定8問で、各問にはA/B/Cの選択肢を三つだけ置く。学習者は正解だと思う選択肢を一つだけチェックする。`### 回答`欄、チェックボックスで回答する旨の案内、正解は生成時に置かない。

選択肢は、無関係で明らかに誤った文ではなく、役割が近い仕組み、必要だが設問の条件には不十分な対策、または条件・主体・適用範囲・順序を一部だけ取り違えた説明を使う。正解だけが設問の全条件を満たすようにし、複数の選択肢を正解として解釈できる曖昧さは作らない。

選択式の推測を理解度の証拠にしないため、`record --mode quick-review` はSessionの採点完了だけを記録し、`語句別理解度.md`、`分野別理解度.md`、`学習履歴.md`を変更しない。不正解のPrimary Termは次回の10分復習候補として再選択でき、採点時には次の学習日用の `復習用/明日復習するべきところ/YYYY-MM-DD.md` にも記載する。

採点では一つだけチェックされた選択肢を `100 / 100` または `0 / 100` とし、未選択・複数選択は未回答とする。各問の採点ブロックは点数と短い解説だけにし、通常・暗記語句用の`良かった点`、`足りない点・誤解`、`模範的な説明`、`次回確認する観点`は置かない。

```markdown
### 採点

Score: 0 / 100

#### 解説

PKCEでは、認可要求ごとに生成したcode_verifierをトークン交換時に提示する。
```

過去の採点済み10分復習にある旧形式の採点ブロックは変更せず、引き続き読み込める。記録と状態判定の詳細は[採点ワークフロー](../skills/security-specialist-trainer/references/採点ワークフロー.md)を読む。
